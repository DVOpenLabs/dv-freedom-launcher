# Local change review

Run `python tools/review_changes.py` before publication. It reads the staged Git contents, compares
them with `HEAD` and prints deterministic facts. Use `--working-tree` to inspect tracked local
changes instead, or `--base <local-ref>` to compare against a reviewed branch. Untracked files are
not publication inputs until staged. This command never uploads code or changes Git.

Private working paths, generated installation artifacts, recognizable private-key blocks, personal
workstation paths, malformed manifests and networking in the TV launcher block publication. New
permissions, Accessibility/notification-listener declarations, privileged operation paths and
workflow edits require human review. `--strict` also returns a failure for those review facts.
Review original data, defaults, device consent, recovery and the complete diff; a short fact list is
not a security audit or a substitute for tests/native acceptance.

These checks adapt the deterministic-review approach of the MIT-licensed
[maintainer-bot](https://github.com/Gathin23/maintainer-bot). No bot code, AI provider, token, external
review call, comment-writing action or automatic merge phase is enabled. The script has no API key
configuration. Adding advisory AI or enabling GitHub Actions requires a separate reviewed change,
with disclosure of code transmission, provider costs, minimum token permissions and head-SHA checks.

Public source includes tests, build instructions, user guides and required licence notices. Research,
roadmaps, audits, detailed device evidence, support bundles and developer session records remain local.
